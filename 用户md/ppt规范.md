# 科研工程 PPT 制作规范

> **用途**：本规范用于约束 Codex / AI 生成、修改和验收科研、工程、科技项目汇报类 PowerPoint。  
> **核心目标**：内容可信、逻辑清楚、版式饱满、重点突出、图表可读、公式规范、备注完整，并尽量避免模板化和 AI 生成痕迹。  
> **执行原则**：本文件既是制作规则，也是最终验收标准。凡明确写明“必须”“不得”的条款均为硬性要求。

# 1. 总体原则

## 1.1 定位

本规范针对：

- 科研项目申报汇报；
- 科技项目立项/中期/结题汇报；
- 工程技术汇报；
- 学术汇报；
- 技术方案论证；
- 研究成果汇报；
- 项目评审、答辩、验收类 PPT。

上述是本规范默认适用的科研工程汇报范围，不把其他类型演示稿强制写成科研报告。用户明确要求制作不同主题时，可迁移信息逻辑、字体检查和渲染验收原则；行业章节、视觉元素及项目参数仍按本次任务确定。

## 1.2 核心视觉原则

整体采用：

> **白色/浅色页面为基础 + 蓝色建立结构 + 黑色承载正文 + 红色精准强调。**

PPT 应具有正式、克制、科研和工程化的视觉特征。

重点不是“设计得花”，而是：

> **让专家快速看懂研究问题、研究方法、关键证据和最终结论。**

## 1.3 核心信息原则

每页应优先回答一个主要问题：

> **这一页到底要让听众知道什么？**

页面信息组织优先采用：

> **结论 → 证据 → 解释/意义**

或者：

> **问题 → 方法 → 结果 → 判断**

不能只是把 Word 报告原文直接搬到 PPT。结论先落在听众能记住的发现上，再用证据解释；条件、局限或待核实事项只在会改变理解或应用时简洁说明，不把每页都写成免责声明。

## 1.4 内容与版式的优先级

发生冲突时，按以下优先级处理：

1. 内容真实性；
2. 核心结论和证据；
3. 可读性；
4. 页面逻辑；
5. 版式平衡；
6. 视觉美观；
7. 装饰效果。

禁止为了“看起来漂亮”删掉关键科研信息。

用户当次要求和指定模板优先；本规范提供通用默认值。项目特定的标题配色组合、章节数量、画幅和页数只用于当前任务，不自动固化为通用要求。

# 2. 制作前：先理解内容与任务

生成 PPT 前必须先分析用户提供的：

- Word/PDF/Excel/图片；
- 项目报告；
- 论文；
- 参考 PPT；
- 用户特别指定的页面结构；
- 用户指定的页数；
- 用户指定的页面比例；
- 用户指定的字体、颜色和风格。

## 2.1 先建立内容结构

从资料中识别本次任务实际涉及的内容，不凭目录清单补造不存在的章节。例如：

- 项目背景；
- 工程概况；
- 研究现状；
- 关键问题；
- 研究目标；
- 研究内容；
- 技术路线；
- 试验/模拟方法；
- 关键结果；
- 对比分析；
- 创新点；
- 工程应用；
- 结论；
- 后续工作。

不能没有分析就直接套模板。只制作报告的一部分时，围绕授权章节及必要上下文组织内容，不必把上述所有模块补成全套。

结题和成果汇报应把主线落在“开展了什么工作、采用什么条件和方法、获得什么证据、形成什么结果、有什么工程意义”。背景和概念只保留理解成果所需的部分。

### 逐页策划与来源映射

新建或整体优化时建立逐页计划：页面核心问题、工作/方法、证据、结论、图表来源、备注补充点和拟用版式；纯局部修改仅记录受影响页面的必要信息，不要求重建全稿逐页计划。每一项关键数值、图、公式和判断均能追溯至文件及章节、图表号或数据位置；来源映射留在工作记录中，不强行占用正式页面。

页数由证据量、汇报时长和可读性共同决定。复杂机理、公式、工况对比和现场验证可分别展开；删减重复概念页，避免先固定页数再压缩全部内容。

## 2.2 参考 PPT 的使用原则

参考 PPT 用于学习：

- 字号层级；
- 颜色关系；
- 图表组织；
- 信息密度；
- 标题层级；
- 重点强调方式；
- 工程汇报的视觉语言。

不得机械复制其：

- Logo；
- 项目名称；
- 页码；
- 内容；
- 数据；
- 与本次目标无关的画幅设置；
- 历史字体问题；
- 其他项目的专属元素。

先查看参考文件的实际页面和代表性内容页，提取可执行的字号、间距、图文比例、信息密度及局部标红方式。仅提取文本或读取主题色，不能代替对参考版式的理解。用户指定其为目标模板时，画幅按第3章继承，保留获授权使用的项目识别元素。

# 3. 页面比例与版心

## 3.1 页面比例不固定

**不得在本规范中强制所有 PPT 使用 16:9。**

每次制作 PPT 时：

> **以用户本次明确指定的页面比例为准。**

例如用户要求：

- 16:9；
- 4:3；
- A4 横向；
- 自定义宽高比；

均应严格执行。

没有另行指定比例时：

1. 优化或续写现有 PPT，读取并保留目标文件的实际宽高；
2. 新建且指定了模板，使用该模板实际宽高；多份参考画幅不一致时，以目标模板为准；
3. 新建且无目标模板，依据使用场景选择并说明。

不得让生成工具默认值覆盖既有画幅。画幅一经确定，在排版前锁定。

## 3.2 页面比例的验收

不得仅根据代码中的设置判断。

生成后必须读取最终 PPT 的实际：

- slide width；
- slide height；

确认实际比例与用户要求一致。

## 3.3 铺满原则

页面比例变化后，**所有版式必须跟随页面比例重新计算**。

不能把 4:3 的版式直接缩放到 16:9，也不能把16:9模板直接压缩到4:3。

用户说“页面铺满”，其含义是：

> **在保证安全留白和可读性的前提下，让主要内容充分利用页面版心，不出现大面积无意义空白。**

不是要求内容贴满四条边。

## 3.4 安全区

根据页面比例动态设置安全区。

原则：

- 左右边缘不得紧贴；
- 上下边缘不得紧贴；
- 页眉、Logo、页码、页脚拥有固定区域；
- 正文、图片、表格不得进入危险边缘。

推荐正文距离页面边缘至少约为页面宽度的 3%–5%。

对于不同页面比例，应按比例重新计算，不得机械使用固定英寸值。

# 4. 页面结构与信息层级

## 4.1 页面必须有结构

页面不应只是“一个标题 + 一小块内容”。

推荐形成：

> 页面标题  
> ↓  
> 核心判断/问题  
> ↓  
> 图表、照片、表格、公式或正文证据  
> ↓  
> 工程含义/结论

## 4.2 信息层级

通常形成四级：

### 一级
页面标题。

### 二级
本页核心问题或核心结论。

### 三级
数据、图表、图片、流程、公式、正文。

### 四级
来源、依据、补充说明、单位等辅助信息。

不能让所有文字：

- 同字号；
- 同粗细；
- 同颜色；
- 同视觉权重。

## 4.3 标题

标题必须能够说明本页内容。

不推荐：

> 研究内容与方法

更推荐：

> 四组典型布设工况与数值模拟方法

不推荐：

> 试验结果

更推荐：

> 不同火源位置下的温度响应与灭火过程

标题可以使用两行，但不得为了排版强行把最后一个词或短语单独换到下一行。

标题、章节导航和本页主题不必重复写三遍。已有多层页眉时，先压紧重复层级，为证据图表保留主体空间；不通过继续放大标题来填白。

# 5. 页面密度与“铺满”原则

这是本规范的重要原则。

## 5.1 不能“太空”

科研 PPT 不是越空越高级。

如果页面主要内容只占页面中央很小一块，而上下、左右存在大面积无意义空白，应：

- 放大核心图片；
- 放大图表；
- 扩大正文版心；
- 增加必要的结果解释；
- 调整为双栏/三栏；
- 将多个相关证据进行合理组合；
- 使用更大的数据展示区域。

**不要让内容只缩在页面中间。**

## 5.2 推荐内容占用率

对于普通研究内容页：

> **主要有效内容建议占可用版心面积的约 65%–90%。**

不是要求几何意义上的“填满”，而是要求页面视觉上具有充分的信息利用率。

以下情况可以低于65%：

- 封面；
- 章节过渡页；
- 极简结论页；
- 单张大型工程照片页；
- 需要突出单个大型公式/模型的页面；
- 用户明确要求留白的页面。

但普通正文页、研究结果页、方法页如果明显低于约60%，应主动检查是否过空。

## 5.3 禁止“大标题 + 小内容块”

禁止出现：

> 大面积标题区域  
> +  
> 中间一个很小的图片/表格  
> +  
> 大面积空白

这是典型的“模板化空页”。

如果内容本身不多：

- 可以增大图表；
- 可以增加关键解释；
- 可以合并相关证据；
- 可以重新设计版式；
- 可以减少标题占用；
- 必要时调整页数。

## 5.4 信息密集与空白的平衡

不是所有页面都要堆满。

正确状态：

> **内容充分 + 层级清楚 + 边缘留白。**

错误状态：

> 大面积空白；

或者：

> 内容塞满 + 字体极小 + 元素互相挤压。

两者都不合格。

# 6. 字体规范

## 6.1 普通文字统一微软雅黑

所有普通文字统一：

> **微软雅黑**

包括：

- 中文；
- 英文；
- 西文；
- 数字；
- 单位；
- 标题；
- 正文；
- 表格；
- 图题；
- 图中说明；
- 页码；
- 页脚；
- 来源说明；
- Speaker Notes 中的普通文字。

禁止：

- Times New Roman；
- Arial；
- Calibri；
- Aptos；
- 黑体；
- 宋体；
- 其他普通字体。

不得出现：

> 中文微软雅黑 + 英文 Arial

这种自动字体切换。

## 6.2 字体必须显式设置

不得依赖 PowerPoint 主题字体。

生成后应检查文本对象实际字体。

包括嵌套 Group 中可访问的文字对象。

普通正文显式采用常规字重；标题、少量关键词或关键数据按层级加粗。检查母版、段落和 run 的继承结果，避免整页正文被隐式加粗。

## 6.3 数学公式例外

MathType / PowerPoint 原生公式中的数学符号属于数学公式对象，其内部数学字体由公式编辑器控制。

但：

- 公式编号；
- 公式说明；
- 变量定义；
- 单位；
- 公式上下的普通文字；

仍使用微软雅黑。

原始证据图片、扫描材料和公式预览中的文字不属于可直接设置字体的普通文本对象。优先在有源数据和授权的条件下重绘；保留原图时不得为统一字体篡改证据，也不得把图片内文字算作已完成字体替换。

# 7. 字号规范

## 7.1 标准字号层级

推荐字号：

| 对象 | 字号 |
|---|---:|
| 封面主标题 | 40–44 pt |
| 封面副标题/单位 | 20–28 pt |
| 页面一级标题 | 28–32 pt |
| 页面二级标题 | 24–26 pt |
| 常规正文 | **20–24 pt** |
| 常规正文首选 | **24 pt** |
| 较长正文 | 20–22 pt |
| 信息密集型正文 | 16–18 pt |
| 图题/表题 | 14–16 pt |
| 图表内部文字 | 12–16 pt |
| 表格表头 | 12–14 pt |
| 表格正文 | 12–14 pt |
| 页脚/页码 | 10–12 pt |
| 来源/依据 | 9–10 pt |

## 7.2 正文不是固定16–18 pt

原则必须明确：

> **24 pt 是常规正文首选。**

只有页面信息密集时才下降：

> 24 → 22 → 20 → 18 → 16

不能一生成 PPT 就把所有正文设为16–18 pt。

## 7.3 禁止自动缩放字号

禁止出现：

- 20.2 pt；
- 17.2 pt；
- 15.8 pt；
- 14.2 pt；
- 13.5 pt；
- 12.8 pt；

等由程序自动缩放产生的非标准字号。

原则上使用固定字号档位：

> 44 / 40 / 32 / 28 / 26 / 24 / 22 / 20 / 18 / 16 / 14 / 12 / 10 / 9 pt

## 7.4 文字放不下时

禁止：

> 放不下 → 自动缩小字体。

正确顺序：

1. 删除重复信息；
2. 压缩无效表达；
3. 改变文字组织；
4. 扩大内容区域；
5. 调整版式；
6. 拆页；
7. 最后才在允许的字号档位中降低一级。

# 8. 颜色规范

## 8.1 核心关系

采用：

> **蓝色建立结构 + 黑色承载正文 + 红色精准强调。**

## 8.2 推荐颜色

| 用途 | 颜色 |
|---|---|
| 标准蓝 | `#0070C0` |
| 深蓝 | `#05398C` |
| 正文黑 | `#151515` |
| 标准红 | `#FF0000` |
| 深红 | `#C00000` |
| 辅助灰 | `#5C6570` |
| 浅蓝 | `#B9CDE5` |
| 极浅蓝 | `#EDF4F9` |

## 8.3 使用原则

### 标准蓝
用于：

- 二级标题；
- 表头；
- 流程；
- 图表结构；
- 标签；
- 辅助线。

### 深蓝
用于：

- 一级结构；
- 章节编号；
- 重要结构元素。

### 黑色
用于：

- 普通正文；
- 一般说明；
- 普通表格文字。

### 红色
用于：

- 关键技术词；
- 核心参数；
- 关键数字；
- 核心结论；
- 重要判断；
- 创新点；
- 需要专家重点关注的信息。

红色不能成为普通正文颜色。

# 9. 红色关键词局部强调

这是本规范的核心视觉特征之一。

## 9.1 黑色主体 + 红色关键词

允许并鼓励在完整黑色句子中，对重要关键词进行局部红色强调。

例如：

> 地中对接适用于**单条隧道连续施工长度大**、无法设置中间竖井等工程条件，可通过两台盾构机相向掘进**缩短施工工期**。

其中：

- 普通说明 = 黑色；
- 核心条件 = 红色；
- 核心结论 = 红色。

## 9.2 红色使用数量

一般：

- 一句话突出1–2处；
- 一段文字突出1–3处；
- 一个页面不能出现大量红色。

## 9.3 禁止

禁止：

- 整段文字全部红色；
- 整个文本框全部红色；
- 一页大量红色；
- 每句话都变红；
- 为了“好看”随意加红。

红色必须具有明确的信息意义。以上禁令针对普通正文；标题按本次模板执行，不能用红色标题代替正文关键词强调。

## 9.4 实际实现与验收

写稿时先确定应被记住的关键词、条件或结论，再将对应文字片段设置为红色 run，周围说明保持黑色。加粗、Markdown 标记、红色线条或红色页眉都不等于正文局部标红。

逐页检查普通内容页是否有应强调却未标红的信息，回读成品中的实际字体颜色，并在渲染图中确认可见。封面、过渡页及无需文字强调的纯图页可按内容处理；不为满足数量而每句加红。

# 10. 正文与文字排版

## 10.1 正文应有信息价值

正文不能只是把报告原文缩小复制。

应优先：

- 提炼研究对象、工作和结论；
- 将分散的试验条件、模型参数与结果重组；
- 归纳影响规律及方案选择依据；
- 解释图表证据的含义；
- 强调工程意义和必要条件。

扩充内容时，增加有来源的条件、比较、结果解释和适用边界。页面优先保留听众必须看到的证据，完整推理与补充说明放入备注；不用口号、同义反复或报告长段原文凑满版面。

## 10.2 长段文字

长段文字确有必要时，可以保留完整句子。

推荐：

> 黑色完整语句 + 红色关键词 + 必要加粗。

不要强行把所有内容变成几个商业化 bullet。

## 10.3 行距

正文行距保持舒适。

不能：

- 行距过小；
- 字距过挤；
- 段落贴在一起。

## 10.4 文本框

文本框必须固定布局。

不得依赖：

- 自动缩小字体；
- 自动扩大文本框；
- 自动改变版式；

来解决排版。

生成后必须检查实际渲染结果。

# 11. 表格规范

## 11.1 总体风格

采用：

> **正式、简洁、科研、工程化。**

优先：

- 白色表体；
- 蓝色表头；
- 浅蓝/浅灰辅助；
- 简洁线条。

禁止：

- 立体表格；
- 厚重阴影；
- 复杂渐变；
- 商业卡片式表格；
- 花哨装饰。

## 11.2 表头

- 标准蓝或深蓝；
- 白色文字；
- 12–14 pt；
- 推荐14 pt；
- 关键单位写在表头。

## 11.3 表体

- 12–14 pt；
- 推荐14 pt；
- 复杂表格最低原则上12 pt。

不能为了塞内容降到9–10 pt。

## 11.4 三线表

科研数据表优先采用三线表思路：

- 顶线；
- 表头分隔线；
- 底线。

原则上：

> 无竖线、无大量内部横线。

如果工程参数表确实需要完整网格，也必须轻量、简洁。

## 11.5 数据格式

同一列同类指标统一单位、对齐方式和显示精度。保留来源数据及其有效精度，不为外观擅自四舍五入、增加有效数字或修改原始值；确需换算或采用统一显示精度时，明确换算/取舍规则并保留可追溯原值。

推荐：

> 指标名称（单位）

例如：

> 纵向间距（m） | 3.7 | 6.0 | 3.7 | 2.7

而不是每个数字重复写单位。

## 11.6 重点数据

可将：

- 推荐值；
- 最优值；
- 临界值；
- 超限值；
- 核心结果；
- 最终选定方案；

局部设置为红色。

不能整列或整张表泛红。

## 11.7 表格过密

如果表格无法保持12–14 pt可读：

> 优先拆表/拆页，不得继续缩小字体。

## 11.8 可编辑与可比较

新生成的参数表、工况表和对比表使用原生可编辑表格；保留原始证据表截图时明确其用途。不能用零散文本框拼出“伪表格”代替可编辑交付。

将工况编号、参数和结果一一对应，区分设定值与测得值。表格用于组织可比较的信息，不仅为增加页面内容而制表。写入后回读行列数、关键单元格和实际样式。

# 12. 图表与图片规范

## 12.1 图表必须服务于结论

每张图都应回答：

> “这张图证明什么？”

不能为了填空白而加入无意义图片。

正文中的工况、测点、时间节点和结论须与所配图片相符。文字指出具体趋势或区域时，用对应标签、简洁引线或邻近说明建立关联；图题说明对象，正文解释发现，备注补充读图过程。

### 素材授权与重绘

按本次授权建立素材来源映射。用户限制章节范围或要求避免与其他部分重复时，逐图核对来源和占用情况，不用其他章节已有图补位。授权工作目录中未用于其他部分的素材，经核对相关性和来源后可用。

可以基于真实资料自行绘制机理图、流程图或参数关系图；示意图与计算/实测结果须能区分。定量重绘必须有可追溯数据，不凭曲线外观编造采样点，也不把生成图当作试验或模拟证据。

## 12.2 图片优先放大

对于研究结果页，如果已有：

- 仿真云图；
- 曲线；
- 工程照片；
- 试验照片；
- 模型图；

且页面明显过空，应优先放大图片，而不是继续增加装饰元素。

## 12.3 图片比例

必须保持原始宽高比。

先检查图片内部白边与无关区域，再等比放大有效内容。裁剪时保留坐标轴、图例、单位、色标、测点标识和必要上下文。图题、结论和来源说明独立预留位置，不能压在有效数据上。

多图同尺寸以有效绘图区为准，不能只让外框相同而曲线图一大一小。局部放大应保留与全图的对应关系。

禁止：

- 拉伸；
- 压扁；
- 非等比例缩放。

## 12.4 图表内部文字

图表内部：

> 12–16 pt优先。

如果图片本身已经包含大量小字，缩放后无法阅读：

1. 放大；
2. 裁剪无关区域；
3. 提取关键区域；
4. 重新绘制；
5. 拆页。

禁止把整页论文/报告截图缩小成一张“看不清的证据图”。

## 12.5 图题

图题一般：

> 14–16 pt

必须能够说明图表对象。

不推荐：

> 图4-17

推荐：

> 不同布设工况下代表测点干粉浓度变化

# 13. 公式与 MathType 规范

## 13.1 MathType 优先

当用户环境中存在并可使用 MathType PowerPoint 插件/加载项时：

> **正式数学公式优先使用 MathType 制作。**

这是硬性优先级。

## 13.2 MathType可用时

优先：

> MathType公式对象

而不是：

- 普通文本框；
- Unicode上下标；
- 拼接字符；
- 公式截图。

复杂公式原则上保持可编辑；仅在第13.3节的最后备用条件成立时采用公式图片，并如实说明交付限制。

## 13.3 MathType不可用时

如果当前环境没有MathType，或无法调用：

1. 优先使用 PowerPoint 原生公式编辑器 / Office Math；
2. 原生公式无法实现时，才允许使用高质量公式图片作为最后备用方案。

不得伪造 MathType OLE 对象。

## 13.4 禁止普通文本模拟复杂公式

例如：

> vₛ = (ρₚ − ρ)gdₚ² / (18μ)

如果页面需要正式展示完整数学公式，不应仅使用普通文本框模拟。

应使用：

- MathType；
- 或 PowerPoint 原生公式。

## 13.5 公式布局

独立公式：

- 居中；
- 与上下正文保持合理间距；
- 需要编号时，编号统一右侧；
- 变量定义放在公式下方。

公式本体视觉大小应与正文协调。

## 13.6 原公式复用与结果对应

来源文件已有真实可编辑公式时，优先复用并核对原对象，减少重新抄写导致的符号、上下标、分母或系数错误。MathType 对象与 Office Math 的选择仍遵守本章优先级。

机理和计算页应把“模型/假设—核心公式—变量与单位—报告中的计算结果—物理意义”连起来；仅展示公式截图或只给最终数字均不足以说明研究工作。按主线选择公式，推导细节可拆页或放备注，不将公式堆成符号墙。

理论估计、数值模拟和实测结果分别标明；理想模型的计算量不直接等同现场有效性能。列举某种受力或机理，不代表它已在实际模型中启用或被单独验证。

## 13.7 MathType环境检测

制作含公式PPT时：

1. 检查用户环境是否有MathType；
2. 有且可调用 → MathType优先；
3. 无/不可调用 → Office Math；
4. 不得假定MathType一定存在；
5. 不得为了满足规范伪造插件对象。

安装记录、注册表路径或可执行文件存在，只能证明存在相应线索；实际调用成功、对象能打开编辑和预览准确应分别验证。复用 OLE 时核对真实嵌入数据与显示内容；二进制一致不能代替编辑能力验证。未完成的检查如实记录，不能宣称已验证可编辑。

- 35 mm
- 3.7 m
- 2.5 m/s
- 10 s
- 60 s
- 10 min

- 2.67 kg/s
- 30 m
- Case1
- Case2

- DPM

禁止：

必须：

应使用不换行空格、整体文本或其他方式保证。

## 14.2 专业术语

项目中的专业术语必须与原始报告保持一致。

不得为了“通俗”而擅自改写专业名词。

## 14.3 数据

不得修改：

- 数值；
- 单位；
- 小数位；
- 试验条件；
- 工况；
- 图表数据；

## 14.4 冲突与缺失

报告正文、表格、曲线或旧 PPT 数值不一致时，追溯原始记录、定义及计算口径。能够确认时记录采用依据；无法确认时保留原始证据，只表达可靠趋势，或暂不采用争议数值，并在备注或校核记录说明必要限制。

不得随意择取最有利数字、改图凑数、虚构误差比例或自行补齐缺测值。来源冲突若影响核心结论，明确列为待核实，不能作为已证实成果交付。

# 15. 研究结果与结论表达

## 15.1 不只展示结果

结果页必须尽可能形成：

> 数据 → 变化 → 判断 → 意义

例如：

不是只放：

> 最大温度：XXX ℃

而应说明：

> 火源附近温度快速上升，喷射后明显下降，说明……

## 15.2 重点结论

核心结论可采用：

- 较大字号；
- 加粗；
- 局部红色；
- 浅蓝背景；
- 位置突出；

但不能做成商业化“大数字卡片”。

## 15.3 结论与证据相称

先陈述数据支持的主要发现，再用准确的动词表达结论强度：数据呈现趋势时说“呈现相同变化趋势”，直接比较结果时再说明一致程度；结论限于已研究的应用情境时，点明该情境即可。避免把结论写成“可能有一定效果，但不能说明……”这类连续退让的句子。

## 15.4 比较口径

理论估计、数值模拟、实验测量和现场观察应标明证据来源。比较多参数工况时说明这是组合工况；涉及测点、时间节点或模型与实验对照时，只补充会影响读者判断的口径。先给出发现和工程含义，再就近交代必要条件。

同一页已有图题、坐标或正文明确交代的条件，备注不必重复；前文已经说明且本页结论未改变范围的限定，后页也不再复述。详细来源核对、未采用数据和内部风险审查放入工作记录。

不要所有页面使用同一模板。

## 16.1 背景页

推荐：

- 背景问题；
- 工程照片；
- 数据；
- 政策/行业需求；
- 一句话结论。

## 16.2 方法页

推荐：

- 技术路线；
- 模型；
- 参数；
- 流程；
- 公式；
- 方法依据。

## 16.3 数据结果页

推荐：

- 大图/大曲线；
- 关键数字；
- 局部解释；
- 结论。

**结果图应尽可能成为页面视觉主体。**

## 16.4 表格页

表格应占主要版面。

不要出现：

> 页面很大 + 表格很小。

## 16.5 多图页

多张图片应：

- 尺寸统一；
- 间距统一；
- 标题统一；
- 重点图突出；
- 图片下方说明简洁。

- 对齐；

不要堆大量正文。

建议：

> 3–5条核心结论

每条包含：

> 结论 + 必要数据/依据

# 17. Speaker Notes 演讲备注

## 17.1 完整写入实际备注

**新建完整 PPT 或整体制作汇报稿时，每页必须有可直接用于汇报的 Speaker Notes，覆盖率100%。**备注写入 PPT 实际 Notes 页；外部讲稿、生成脚本或 Markdown 不能代替成品备注。只修改现有 PPT 的少数页面时，应保留未受影响页面的原备注，并核对、同步更新受改动影响的备注；用户明确要求整份补齐时再检查并补齐100%覆盖。封面和过渡页可简短交代主题与承接，不机械凑字。

## 17.2 页面与讲稿分工

页面承载关键证据和便于扫读的结论；备注补充研究思路、读图方法、解释和承接。备注应使汇报者讲清“开展了什么、证据是什么、结果如何理解、对研究或工程有什么用”，不逐句读屏，也不只是扩写标题。

优先写成连贯、自然、可直接朗读的完整段落。常规页建议80–180字，复杂结果页120–250字，通常2–5句；按信息量和汇报时间调整，不机械凑长度。

## 17.3 自然开场与承接

从研究对象、具体问题、主要发现或与前页的关系切入。例如以“模型采用……”“两组工况的差别主要在……”“温度曲线反映了……”起句，随页面任务变化。

避免逐页用“这一页说明……”“本页展示……”“接下来介绍……”报幕；也不能只更换开头词而保留完全相同的句式。需要承接时点明研究关系，例如由模型建立转向参数比较、由模拟结果转向现场验证，不必每页强行加入转场句。

## 17.4 论证顺序灵活，但判断有依据

优先围绕“做了什么、证据说明什么、结果有什么意义”组织，也可先报主要发现再解释依据。方法条件和适用范围只有在理解结果所必需时才展开；按内容选择顺序，不把固定环节写成逐页模板。

每个重要判断都能找到本页证据或已明确引用的前文依据；已有页面文字不必重复一遍，讲稿应补足听众理解判断所需的中间环节。

## 17.5 不同页面的讲述重点

| 页面类型 | 备注重点 |
|---|---|
| 背景/工程引入 | 具体约束与研究问题，说明本研究为何需要开展；行业背景只讲必要部分 |
| 方法/工况 | 做了什么、为何这样设计，关键条件和参数如何对应，比较是否成立 |
| 机理/公式 | 变量的物理含义、关键假设、控制关系和公式用途，衔接计算结果；不朗读整串符号 |
| 曲线/云图结果 | 解释峰值、转折、分布及其物理过程；坐标、测点或色标不清楚时再补充读图口径 |
| 多图/表格对比 | 点出主要差异、共同趋势和选择依据，不逐项报完所有数字 |
| 实验/现场验证 | 说明观察结果如何支持结论；测量、确认或验证范围有实质差别时再加以区分 |
| 总结/应用 | 回扣研究问题，提炼成果及其工程意义 |

## 17.6 直接、可信地讲结论

备注与页面使用一致的数值、单位和证据口径。开头尽快讲研究动作或发现，随后解释关键证据和意义。不要在每段末尾习惯性添加“仅限本次条件”“不能说明其他情况”“仍需进一步研究”等防范句。

只有当条件会改变本页结论的理解或工程使用时，才在相关句子中交代一次；无需把内部审计、所有未研究情形和假想质疑都讲给听众。资料确实不足以支持核心结论时，简洁说明缺少哪项关键证据及其影响，并相应收窄结论。

## 17.7 语气与可讲性

使用准确但便于口头表达的科研语言，句子长短有变化，避免堆叠名词和反复使用“表明了重要意义”等空泛评价。数值只讲支撑判断所需的关键项；复杂清单让听众看表，讲稿解释其中关系。

例如，结果页可以先讲曲线反映的过程，再解释关键变化及其工程意义；若具体工况本身决定结论范围，就在对应句子中点明。无需在每页结尾重复一条固定的“本次条件下”提示。

## 17.8 连续通读与回读验收

写完后按实际汇报顺序连续通读，检查开场是否重复、前后是否衔接、术语和语气是否一致、是否重复解释同一概念，以及限定说明是否在正文、图题和备注中反复出现。跨页拆开的推导与对比应能连贯讲述。

从最终 PPT 回读实际 Notes 正文，剔除默认日期、页码等占位内容再统计覆盖率；核对页与稿对应、长度是否合适、普通备注文字是否为微软雅黑。判断内容可讲性不能只靠“非空”或字数达标。

---

# 18. 反模板化与反 AI 痕迹

## 18.1 禁止商业化模板

避免：

- 三个彩色卡片；
- KPI大数字；
- 大面积渐变；
- 玻璃拟态；
- 霓虹色；
- 互联网产品UI；
- 无意义图标墙；
- 过度圆角；
- 复杂阴影。

尤其避免把一个数字孤立放大，再配标签作为页面中心。将其缩小后继续保留同样的数字标签结构，也没有解决表达问题。应把数值放回“对象、条件、结果”的完整语句、图中标注或规范表格中，并保留单位和证据关系。

用户要求去掉某种表达形式时，先识别它承载的信息，再用文字、图表、流程或自行绘制的机理图重新表达；不只缩小原元素，也不直接丢掉有价值的内容。

## 18.2 不要每页一个模板

页面可以有统一视觉语言，但版式应根据内容变化。

允许：

- 单图；
- 双图；
- 三图；
- 图文；
- 表格；
- 流程；
- 对比；
- 公式；
- 数据曲线；
- 工程照片；

不同页面采用不同布局。

## 18.3 不要为了“设计”制造内容

禁止：

> 页面太空 → 加几个圆圈、线条、图标、装饰卡片。

正确：

> 页面太空 → 放大已有证据、重组内容、补充必要解释或调整版式。

# 19. PPT 生成工作流

新建或整体优化按以下依赖顺序完成，下列产物以可核查为准。局部修改只处理受影响内容与关联页面，不为微小调整重复全套资料读取、策划和全稿渲染；涉及全局样式或论证主线变化时扩大检查范围。

1. **读取与诊断**：读取本次规范、授权资料及目标/参考 PPT 的相关内容；查看实际页面，识别画幅、模板特征、事实冲突、布局问题和可复用素材。用户要求先分析时，先交付分析，不提前改文件。
2. **建立逐页计划**：按第2章明确主线、页数、证据、来源、布局和备注补充点；区分概念介绍与已完成工作。
3. **锁定画幅与版心**：按第3章确定实际宽高，划定标题、主体、图题和页脚区域，再计算元素位置。
4. **制作内容与图表**：先保证事实和论证正确，再按内容选择图文、公式、表格或对比布局；所用数据和素材逐项可追溯。
5. **实现视觉层级**：落实第6–12章的字体、字重、字号、局部红字、表格和图文对应，解决大面积无效留白与过密问题。
6. **处理正式公式**：按第13章检测实际可用能力，优先复用真实可编辑对象，核对符号、结果及显示。
7. **完成演讲备注**：按第17章写入全部 Notes，连续通读并核对证据口径。
8. **结构与内容检查**：读取最终文件实际属性、对象和 Notes，检查第20章各项，而非只检查生成参数。
9. **实际打开并渲染**：在可用目标软件中打开最终文件并导出 PDF 或逐页图片；检查修复提示、缺图、对象预览和字体替换。
10. **逐页视觉验收与修正**：按真实放映阅读尺度审查全部页面，修正后重新检查受影响页面；修改波及母版或全局样式时，复查全部受影响页。
11. **交付与说明**：核验最终成品、原文件保护和输出位置；简要报告实际改动、页数、备注覆盖以及尚未解决的实质问题。

“代码执行成功”“文件已生成”或“自动检查通过”均不单独代表制作完成。

# 20. 自动检查与渲染验收

## 20.1 页面检查

必须检查：

- 实际页面宽度；
- 实际页面高度；
- 页面比例是否符合用户要求。

## 20.2 字体检查

检查所有可访问文本对象：

- 是否微软雅黑；
- 是否残留Arial；
- 是否残留Times New Roman；
- 是否残留Calibri；
- 是否残留其他普通字体；
- 东亚、西文、数字及备注的实际字体是否都已设置；
- 是否因主题/母版继承出现整页加粗或层级混乱。

原图和公式内部字体按第6.3节处理，不虚报替换结果。

## 20.3 字号检查

检查：

- 标题；
- 正文；
- 表格；
- 图题；
- 页脚；
- 图表文字。

重点发现：

> 非标准字号。

## 20.4 文本排版检查

检查：

- 溢出；
- 裁切；
- 重叠；
- 遮挡；
- 标题孤行；
- 数字单位断行；
- 页脚冲突。

## 20.5 页面密度检查

重点检查：

> **普通内容页是否明显过空。**

如果主要内容集中在页面中部且占比明显偏小，应重新布局。

优先：

- 放大图片；
- 放大图表；
- 扩大正文；
- 增加合理的结果解释；
- 调整双栏比例；
- 合并相关证据。

不要用装饰填空。

## 20.6 表格检查

检查：

- 表头颜色；
- 表体颜色；
- 字号；
- 对齐；
- 单位；
- 小数位；
- 表格是否过密；
- 是否可读；
- 要求可编辑的表是否为真实原生表格，关键单元格是否与来源一致。

## 20.7 公式检查

按第13章检查公式对象类型、真实嵌入内容、符号与结果、预览完整性以及实际编辑能力。区分“文件包含对象”“软件能显示”“已测试打开编辑”三种状态；记录实际完成的验证，不把其中一种当作全部通过。

## 20.8 Speaker Notes检查

新建完整 PPT 或整体制作任务按第17.8节回读最终文件并连续通读，Notes 正文覆盖率须为100%；局部修改任务核对受影响页面及必要承接关系，不把历史未涉及页面的原有缺项当作本次必须重写的范围。检查自然开场、读图解释、页稿一致和证据口径；空模板、复制正文或重复报幕不能算作合格备注。

## 20.9 渲染检查

必须实际查看最终渲染结果。

至少检查：

- 页面是否太空；
- 页面是否太挤；
- 标题是否重叠；
- 正文是否被裁切；
- 表格是否可读；
- 图表是否可读；
- 图片是否变形；
- 重要正文关键词是否实际标红、是否过多；
- 图题、正文判断与图片对象是否对应；
- 图片内部白边是否导致有效绘图区过小；
- 页面视觉是否统一。

缩略图适合检查全局节奏，关键图表和密集页还须放大检查标签、单位与数据。自动容量或边界检查不能代替人工目视；渲染结果必须来自本次最终成品。

## 20.10 来源与事实核查

将最终可见内容及备注与逐页来源映射核对：素材授权范围、关键数值、公式、工况和结果一致；争议数据有处理依据；结论未超出证据。重点检查旧 PPT 遗留错误是否随复制被带入。

## 20.11 局部红字专项检查

按第9.4节同时回读颜色 run 和查看渲染效果，确认强调落在正文的关键词、条件或结论上。红色标题、红色装饰及隐藏文本不计作正文标红的落实。

# 21. 最终交付标准

只有同时满足以下条件，才能判定 PPT 制作完成。

## 内容

- [ ] 关键数值、图表、公式和判断有逐页来源映射，素材在授权范围内；
- [ ] 数据没有擅自修改；
- [ ] 研究逻辑清楚；
- [ ] 每页有明确重点；
- [ ] 结论与证据匹配，冲突数值和理论/模拟/实测边界已妥善处理。

## 页面

- [ ] 页面比例符合用户本次要求；
- [ ] 页面没有明显无意义空白；
- [ ] 页面没有严重拥挤；
- [ ] 内容充分利用版心；
- [ ] 图片、表格和图表大小合理。

## 字体

- [ ] 普通文字全部微软雅黑；
- [ ] 英文和数字也是微软雅黑；
- [ ] 没有Times New Roman；
- [ ] 没有Arial；
- [ ] 没有Calibri；
- [ ] 没有其他非规定普通字体。

## 字号

- [ ] 常规正文优先24 pt；
- [ ] 信息密集页可使用16–18 pt；
- [ ] 表格正文12–14 pt；
- [ ] 标题层级统一；
- [ ] 没有大量自动缩放的小数字号。

## 颜色

- [ ] 蓝色建立结构；
- [ ] 黑色承载正文；
- [ ] 正文关键词已按语义实际局部标红，经过 run 回读和渲染确认；
- [ ] 没有整段泛红；
- [ ] 没有无意义多色混搭。

## 表格

- [ ] 表格简洁，要求可编辑的表为原生对象；
- [ ] 表头统一；
- [ ] 字号可读；
- [ ] 单位规范；
- [ ] 小数位统一；
- [ ] 重点数据可局部红色；
- [ ] 没有为了塞内容而缩小到不可读。

## 图表

- [ ] 图片没有变形；
- [ ] 图表可读；
- [ ] 坐标轴和图例清楚；
- [ ] 图表真正服务于结论；
- [ ] 结果图没有缩得过小。

## 公式

- [ ] 有MathType且可调用时优先MathType；
- [ ] MathType公式保持可编辑；
- [ ] 无MathType时优先Office Math；
- [ ] 没有用普通文本模拟复杂公式，显示与编辑能力的核验状态如实记录。

## 演讲备注

- [ ] 新建完整 PPT 或整体制作稿已回读确认每页实际 Notes 正文非空、覆盖率100%；局部修改已核对受影响页面的 Notes 且未擅自重写其他页面；
- [ ] 备注不是简单复制正文；
- [ ] 备注自然起句、解释证据与意义，连续通读衔接顺畅，能够直接用于实际汇报；
- [ ] 备注与当前页面内容一致；
- [ ] 没有编造数据和结论。

## 最终视觉

- [ ] 已实际渲染；
- [ ] 已逐页查看；
- [ ] 无溢出；
- [ ] 无遮挡；
- [ ] 无错误断行；
- [ ] 无明显空页；
- [ ] 无明显模板化；
- [ ] 无明显AI生成痕迹。

## 交付与版本保护

输出到用户指定位置；未指定时遵守当前全局规则的默认输出目录。用户要求保留旧版或增加版本后缀时，保留原文件并另存新版本，不覆盖或删除已有版本。

修改既有 PPT 时先建立工作副本；仅在明确授权直接修改时写入源文件。交付前确认输出文件存在且可重新打开，必要时比较源文件哈希以确认未改动。向用户提供实际成品路径、页数及实质调整，区分已验证结果与仍待核实项；内部脚本、缓存和校核材料不写进正式页面或演讲稿。
