# 科研工程 PPT 制作规范

> **用途**：本规范用于约束 Codex / AI 生成、修改和验收科研、工程、科技项目汇报类 PowerPoint。  
> **核心目标**：内容可信、逻辑清楚、版式饱满、重点突出、图表可读、公式规范、备注完整，并尽量避免模板化和 AI 生成痕迹。  
> **执行原则**：本文件既是制作规则，也是最终验收标准。凡明确写明“必须”“不得”的条款均为硬性要求。

# 1. 总体原则

## 1.1 定位

本规范针对：

- 科研项目申报汇报；
- 科技项目立项/中期/结题汇报；
- 工程技术汇报；
- 学术汇报；
- 技术方案论证；
- 研究成果汇报；
- 项目评审、答辩、验收类 PPT。

不是商业宣传 PPT，也不是互联网产品展示页。

## 1.2 核心视觉原则

整体采用：

> **白色/浅色页面为基础 + 蓝色建立结构 + 黑色承载正文 + 红色精准强调。**

PPT 应具有正式、克制、科研和工程化的视觉特征。

重点不是“设计得花”，而是：

> **让专家快速看懂研究问题、研究方法、关键证据和最终结论。**

## 1.3 核心信息原则

每页应优先回答一个主要问题：

> **这一页到底要让听众知道什么？**

页面信息组织优先采用：

> **结论 → 证据 → 解释/意义**

或者：

> **问题 → 方法 → 结果 → 判断**

不能只是把 Word 报告原文直接搬到 PPT。

## 1.4 内容与版式的优先级

发生冲突时，按以下优先级处理：

1. 内容真实性；
2. 核心结论和证据；
3. 可读性；
4. 页面逻辑；
5. 版式平衡；
6. 视觉美观；
7. 装饰效果。

禁止为了“看起来漂亮”删掉关键科研信息。

# 2. 制作前：先理解内容与任务

生成 PPT 前必须先分析用户提供的：

- Word/PDF/Excel/图片；
- 项目报告；
- 论文；
- 参考 PPT；
- 用户特别指定的页面结构；
- 用户指定的页数；
- 用户指定的页面比例；
- 用户指定的字体、颜色和风格。

## 2.1 先建立内容结构

至少识别：

- 项目背景；
- 工程概况；
- 研究现状；
- 关键问题；
- 研究目标；
- 研究内容；
- 技术路线；
- 试验/模拟方法；
- 关键结果；
- 对比分析；
- 创新点；
- 工程应用；
- 结论；
- 后续工作。

不能没有分析就直接套模板。

## 2.2 参考 PPT 的使用原则

参考 PPT 用于学习：

- 字号层级；
- 颜色关系；
- 图表组织；
- 信息密度；
- 标题层级；
- 重点强调方式；
- 工程汇报的视觉语言。

不得机械复制其：

- Logo；
- 项目名称；
- 页码；
- 内容；
- 数据；
- 页面比例；
- 历史字体问题；
- 其他项目的专属元素。

# 3. 页面比例与版心

## 3.1 页面比例不固定

**不得在本规范中强制所有 PPT 使用 16:9。**

每次制作 PPT 时：

> **以用户本次明确指定的页面比例为准。**

例如用户要求：

- 16:9；
- 4:3；
- A4 横向；
- 自定义宽高比；

均应严格执行。

如果用户没有指定比例，应根据使用场景选择合理比例，并在制作前明确采用的比例。

## 3.2 页面比例的验收

不得仅根据代码中的设置判断。

生成后必须读取最终 PPT 的实际：

- slide width；
- slide height；

确认实际比例与用户要求一致。

## 3.3 铺满原则

页面比例变化后，**所有版式必须跟随页面比例重新计算**。

不能把 4:3 的版式直接缩放到 16:9，也不能把16:9模板直接压缩到4:3。

用户说“页面铺满”，其含义是：

> **在保证安全留白和可读性的前提下，让主要内容充分利用页面版心，不出现大面积无意义空白。**

不是要求内容贴满四条边。

## 3.4 安全区

根据页面比例动态设置安全区。

原则：

- 左右边缘不得紧贴；
- 上下边缘不得紧贴；
- 页眉、Logo、页码、页脚拥有固定区域；
- 正文、图片、表格不得进入危险边缘。

推荐正文距离页面边缘至少约为页面宽度的 3%–5%。

对于不同页面比例，应按比例重新计算，不得机械使用固定英寸值。

# 4. 页面结构与信息层级

## 4.1 页面必须有结构

页面不应只是“一个标题 + 一小块内容”。

推荐形成：

> 页面标题  
> ↓  
> 核心判断/问题  
> ↓  
> 图表、照片、表格、公式或正文证据  
> ↓  
> 工程含义/结论

## 4.2 信息层级

通常形成四级：

### 一级
页面标题。

### 二级
本页核心问题或核心结论。

### 三级
数据、图表、图片、流程、公式、正文。

### 四级
来源、依据、补充说明、单位等辅助信息。

不能让所有文字：

- 同字号；
- 同粗细；
- 同颜色；
- 同视觉权重。

## 4.3 标题

标题必须能够说明本页内容。

不推荐：

> 研究内容与方法

更推荐：

> 四组典型布设工况与数值模拟方法

不推荐：

> 试验结果

更推荐：

> 不同火源位置下的温度响应与灭火过程

标题可以使用两行，但不得为了排版强行把最后一个词或短语单独换到下一行。

# 5. 页面密度与“铺满”原则

这是本规范的重要原则。

## 5.1 不能“太空”

科研 PPT 不是越空越高级。

如果页面主要内容只占页面中央很小一块，而上下、左右存在大面积无意义空白，应：

- 放大核心图片；
- 放大图表；
- 扩大正文版心；
- 增加必要的结果解释；
- 调整为双栏/三栏；
- 将多个相关证据进行合理组合；
- 使用更大的数据展示区域。

**不要让内容只缩在页面中间。**

## 5.2 推荐内容占用率

对于普通研究内容页：

> **主要有效内容建议占可用版心面积的约 65%–90%。**

不是要求几何意义上的“填满”，而是要求页面视觉上具有充分的信息利用率。

以下情况可以低于65%：

- 封面；
- 章节过渡页；
- 极简结论页；
- 单张大型工程照片页；
- 需要突出单个大型公式/模型的页面；
- 用户明确要求留白的页面。

但普通正文页、研究结果页、方法页如果明显低于约60%，应主动检查是否过空。

## 5.3 禁止“大标题 + 小内容块”

禁止出现：

> 大面积标题区域  
> +  
> 中间一个很小的图片/表格  
> +  
> 大面积空白

这是典型的“模板化空页”。

如果内容本身不多：

- 可以增大图表；
- 可以增加关键解释；
- 可以合并相关证据；
- 可以重新设计版式；
- 可以减少标题占用；
- 必要时调整页数。

## 5.4 信息密集与空白的平衡

不是所有页面都要堆满。

正确状态：

> **内容充分 + 层级清楚 + 边缘留白。**

错误状态：

> 大面积空白；

或者：

> 内容塞满 + 字体极小 + 元素互相挤压。

两者都不合格。

# 6. 字体规范

## 6.1 普通文字统一微软雅黑

所有普通文字统一：

> **微软雅黑**

包括：

- 中文；
- 英文；
- 西文；
- 数字；
- 单位；
- 标题；
- 正文；
- 表格；
- 图题；
- 图中说明；
- 页码；
- 页脚；
- 来源说明；
- Speaker Notes 中的普通文字。

禁止：

- Times New Roman；
- Arial；
- Calibri；
- Aptos；
- 黑体；
- 宋体；
- 其他普通字体。

不得出现：

> 中文微软雅黑 + 英文 Arial

这种自动字体切换。

## 6.2 字体必须显式设置

不得依赖 PowerPoint 主题字体。

生成后应检查文本对象实际字体。

包括嵌套 Group 中可访问的文字对象。

## 6.3 数学公式例外

MathType / PowerPoint 原生公式中的数学符号属于数学公式对象，其内部数学字体由公式编辑器控制。

但：

- 公式编号；
- 公式说明；
- 变量定义；
- 单位；
- 公式上下的普通文字；

仍使用微软雅黑。

# 7. 字号规范

## 7.1 标准字号层级

推荐字号：

| 对象 | 字号 |
|---|---:|
| 封面主标题 | 40–44 pt |
| 封面副标题/单位 | 20–28 pt |
| 页面一级标题 | 28–32 pt |
| 页面二级标题 | 24–26 pt |
| 常规正文 | **20–24 pt** |
| 常规正文首选 | **24 pt** |
| 较长正文 | 20–22 pt |
| 信息密集型正文 | 16–18 pt |
| 图题/表题 | 14–16 pt |
| 图表内部文字 | 12–16 pt |
| 表格表头 | 12–14 pt |
| 表格正文 | 12–14 pt |
| 页脚/页码 | 10–12 pt |
| 来源/依据 | 9–10 pt |

## 7.2 正文不是固定16–18 pt

原则必须明确：

> **24 pt 是常规正文首选。**

只有页面信息密集时才下降：

> 24 → 22 → 20 → 18 → 16

不能一生成 PPT 就把所有正文设为16–18 pt。

## 7.3 禁止自动缩放字号

禁止出现：

- 20.2 pt；
- 17.2 pt；
- 15.8 pt；
- 14.2 pt；
- 13.5 pt；
- 12.8 pt；

等由程序自动缩放产生的非标准字号。

原则上使用固定字号档位：

> 44 / 40 / 32 / 28 / 26 / 24 / 22 / 20 / 18 / 16 / 14 / 12 / 10 / 9 pt

## 7.4 文字放不下时

禁止：

> 放不下 → 自动缩小字体。

正确顺序：

1. 删除重复信息；
2. 压缩无效表达；
3. 改变文字组织；
4. 扩大内容区域；
5. 调整版式；
6. 拆页；
7. 最后才在允许的字号档位中降低一级。

# 8. 颜色规范

## 8.1 核心关系

采用：

> **蓝色建立结构 + 黑色承载正文 + 红色精准强调。**

## 8.2 推荐颜色

| 用途 | 颜色 |
|---|---|
| 标准蓝 | `#0070C0` |
| 深蓝 | `#05398C` |
| 正文黑 | `#151515` |
| 标准红 | `#FF0000` |
| 深红 | `#C00000` |
| 辅助灰 | `#5C6570` |
| 浅蓝 | `#B9CDE5` |
| 极浅蓝 | `#EDF4F9` |

## 8.3 使用原则

### 标准蓝
用于：

- 二级标题；
- 表头；
- 流程；
- 图表结构；
- 标签；
- 辅助线。

### 深蓝
用于：

- 一级结构；
- 章节编号；
- 重要结构元素。

### 黑色
用于：

- 普通正文；
- 一般说明；
- 普通表格文字。

### 红色
用于：

- 关键技术词；
- 核心参数；
- 关键数字；
- 核心结论；
- 重要判断；
- 创新点；
- 需要专家重点关注的信息。

红色不能成为普通正文颜色。

# 9. 红色关键词局部强调

这是本规范的核心视觉特征之一。

## 9.1 黑色主体 + 红色关键词

允许并鼓励在完整黑色句子中，对重要关键词进行局部红色强调。

例如：

> 地中对接适用于**单条隧道连续施工长度大**、无法设置中间竖井等工程条件，可通过两台盾构机相向掘进**缩短施工工期**。

其中：

- 普通说明 = 黑色；
- 核心条件 = 红色；
- 核心结论 = 红色。

## 9.2 红色使用数量

一般：

- 一句话突出1–2处；
- 一段文字突出1–3处；
- 一个页面不能出现大量红色。

## 9.3 禁止

禁止：

- 整段文字全部红色；
- 整个文本框全部红色；
- 一页大量红色；
- 每句话都变红；
- 为了“好看”随意加红。

红色必须具有明确的信息意义。

# 10. 正文与文字排版

## 10.1 正文应有信息价值

正文不能只是把报告原文缩小复制。

应优先：

- 提炼；
- 重组；
- 归纳；
- 解释；
- 强调结论。

## 10.2 长段文字

长段文字确有必要时，可以保留完整句子。

推荐：

> 黑色完整语句 + 红色关键词 + 必要加粗。

不要强行把所有内容变成几个商业化 bullet。

## 10.3 行距

正文行距保持舒适。

不能：

- 行距过小；
- 字距过挤；
- 段落贴在一起。

## 10.4 文本框

文本框必须固定布局。

不得依赖：

- 自动缩小字体；
- 自动扩大文本框；
- 自动改变版式；

来解决排版。

生成后必须检查实际渲染结果。

# 11. 表格规范

## 11.1 总体风格

采用：

> **正式、简洁、科研、工程化。**

优先：

- 白色表体；
- 蓝色表头；
- 浅蓝/浅灰辅助；
- 简洁线条。

禁止：

- 立体表格；
- 厚重阴影；
- 复杂渐变；
- 商业卡片式表格；
- 花哨装饰。

## 11.2 表头

- 标准蓝或深蓝；
- 白色文字；
- 12–14 pt；
- 推荐14 pt；
- 关键单位写在表头。

## 11.3 表体

- 12–14 pt；
- 推荐14 pt；
- 复杂表格最低原则上12 pt。

不能为了塞内容降到9–10 pt。

## 11.4 三线表

科研数据表优先采用三线表思路：

- 顶线；
- 表头分隔线；
- 底线。

原则上：

> 无竖线、无大量内部横线。

如果工程参数表确实需要完整网格，也必须轻量、简洁。

## 11.5 数据格式

同一列：

- 小数位统一；
- 单位统一；
- 数字对齐方式统一。

推荐：

> 指标名称（单位）

例如：

> 纵向间距（m） | 3.7 | 6.0 | 3.7 | 2.7

而不是每个数字重复写单位。

## 11.6 重点数据

可将：

- 推荐值；
- 最优值；
- 临界值；
- 超限值；
- 核心结果；
- 最终选定方案；

局部设置为红色。

不能整列或整张表泛红。

## 11.7 表格过密

如果表格无法保持12–14 pt可读：

> 优先拆表/拆页，不得继续缩小字体。

# 12. 图表与图片规范

## 12.1 图表必须服务于结论

每张图都应回答：

> “这张图证明什么？”

不能为了填空白而加入无意义图片。

## 12.2 图片优先放大

对于研究结果页，如果已有：

- 仿真云图；
- 曲线；
- 工程照片；
- 试验照片；
- 模型图；

且页面明显过空，应优先放大图片，而不是继续增加装饰元素。

## 12.3 图片比例

必须保持原始宽高比。

禁止：

- 拉伸；
- 压扁；
- 非等比例缩放。

## 12.4 图表内部文字

图表内部：

> 12–16 pt优先。

如果图片本身已经包含大量小字，缩放后无法阅读：

1. 放大；
2. 裁剪无关区域；
3. 提取关键区域；
4. 重新绘制；
5. 拆页。

禁止把整页论文/报告截图缩小成一张“看不清的证据图”。

## 12.5 图题

图题一般：

> 14–16 pt

必须能够说明图表对象。

不推荐：

> 图4-17

推荐：

> 不同布设工况下代表测点干粉浓度变化

# 13. 公式与 MathType 规范

## 13.1 MathType 优先

当用户环境中存在并可使用 MathType PowerPoint 插件/加载项时：

> **正式数学公式优先使用 MathType 制作。**

这是硬性优先级。

## 13.2 MathType可用时

优先：

> MathType公式对象

而不是：

- 普通文本框；
- Unicode上下标；
- 拼接字符；
- 公式截图。

复杂公式必须保持可编辑。

## 13.3 MathType不可用时

如果当前环境没有MathType，或无法调用：

1. 优先使用 PowerPoint 原生公式编辑器 / Office Math；
2. 原生公式无法实现时，才允许使用高质量公式图片作为最后备用方案。

不得伪造 MathType OLE 对象。

## 13.4 禁止普通文本模拟复杂公式

例如：

> vₛ = (ρₚ − ρ)gdₚ² / (18μ)

如果页面需要正式展示完整数学公式，不应仅使用普通文本框模拟。

应使用：

- MathType；
- 或 PowerPoint 原生公式。

## 13.5 公式布局

独立公式：

- 居中；
- 与上下正文保持合理间距；
- 需要编号时，编号统一右侧；
- 变量定义放在公式下方。

公式本体视觉大小应与正文协调。

## 13.6 MathType环境检测

制作含公式PPT时：

1. 检查用户环境是否有MathType；
2. 有且可调用 → MathType优先；
3. 无/不可调用 → Office Math；
4. 不得假定MathType一定存在；
5. 不得为了满足规范伪造插件对象。

# 14. 数字、单位、符号与专业术语

## 14.1 数字与单位不得拆行

以下必须视为不可拆分的信息单元：

- 35 mm
- 3.7 m
- 2.5 m/s
- 10 s
- 60 s
- 10 min
- 8 kg
- 2.67 kg/s
- 30 m
- Case1
- Case2
- k-ε
- DPM

禁止：

> 3.4  
> m

必须：

> 3.4 m

应使用不换行空格、整体文本或其他方式保证。

## 14.2 专业术语

项目中的专业术语必须与原始报告保持一致。

不得为了“通俗”而擅自改写专业名词。

## 14.3 数据

不得修改：

- 数值；
- 单位；
- 小数位；
- 试验条件；
- 工况；
- 图表数据；

除非用户明确要求。

# 15. 研究结果与结论表达

## 15.1 不只展示结果

结果页必须尽可能形成：

> 数据 → 变化 → 判断 → 意义

例如：

不是只放：

> 最大温度：XXX ℃

而应说明：

> 火源附近温度快速上升，喷射后明显下降，说明……

## 15.2 重点结论

核心结论可采用：

- 较大字号；
- 加粗；
- 局部红色；
- 浅蓝背景；
- 位置突出；

但不能做成商业化“大数字卡片”。

## 15.3 不夸大

如果数据只能说明：

> “趋势一致”

就不要写成：

> “完全一致”。

如果只能说明：

> “具有一定适用性”

就不要写成：

> “完全适用”。

结论强度必须与证据强度一致。

# 16. 页面类型与版式策略

不要所有页面使用同一模板。

## 16.1 背景页

推荐：

- 背景问题；
- 工程照片；
- 数据；
- 政策/行业需求；
- 一句话结论。

## 16.2 方法页

推荐：

- 技术路线；
- 模型；
- 参数；
- 流程；
- 公式；
- 方法依据。

## 16.3 数据结果页

推荐：

- 大图/大曲线；
- 关键数字；
- 局部解释；
- 结论。

**结果图应尽可能成为页面视觉主体。**

## 16.4 表格页

表格应占主要版面。

不要出现：

> 页面很大 + 表格很小。

## 16.5 多图页

多张图片应：

- 尺寸统一；
- 间距统一；
- 标题统一；
- 重点图突出；
- 图片下方说明简洁。

## 16.6 对比页

推荐左右对比或上下对比。

对比对象必须：

- 对齐；
- 使用相同尺度；
- 使用相同指标；
- 具有明确结论。

## 16.7 结论页

不要堆大量正文。

建议：

> 3–5条核心结论

每条包含：

> 结论 + 必要数据/依据

---

# 17. Speaker Notes 演讲备注

## 17.1 100%覆盖

> **每一张 PPT 必须存在 Speaker Notes。**

覆盖率：

> **100%**

不得有空备注页面。

## 17.2 备注不是复制正文

备注应回答：

1. 本页讲什么；
2. 核心证据是什么；
3. 数据/图片说明什么；
4. 得到什么判断；
5. 对工程或研究有什么意义。

## 17.3 不同页面的备注

### 背景页
说明为什么研究。

### 方法页
说明采用什么方法、为什么采用。

### 结果页
解释数据意味着什么。

### 对比页
解释差异和选择依据。

### 结论页
告诉听众最终需要记住什么。

## 17.4 备注写作

建议每页约：

> 80–180字

复杂结果页可：

> 120–250字

不要机械凑字数。

避免大量：

- “这一页……”
- “这里……”
- “我们可以看到……”

备注必须像真实汇报语言。

---

# 18. 反模板化与反 AI 痕迹

## 18.1 禁止商业化模板

避免：

- 三个彩色卡片；
- KPI大数字；
- 大面积渐变；
- 玻璃拟态；
- 霓虹色；
- 互联网产品UI；
- 无意义图标墙；
- 过度圆角；
- 复杂阴影。

## 18.2 不要每页一个模板

页面可以有统一视觉语言，但版式应根据内容变化。

允许：

- 单图；
- 双图；
- 三图；
- 图文；
- 表格；
- 流程；
- 对比；
- 公式；
- 数据曲线；
- 工程照片；

不同页面采用不同布局。

## 18.3 不要为了“设计”制造内容

禁止：

> 页面太空 → 加几个圆圈、线条、图标、装饰卡片。

正确：

> 页面太空 → 放大已有证据、重组内容、补充必要解释或调整版式。

# 19. PPT 生成工作流

必须按照以下顺序：

## Step 1：读取资料

完整读取用户提供的：

- 文档；
- 表格；
- 图片；
- 参考PPT；
- 规范。

## Step 2：建立内容结构

确定：

- 页数；
- 页面顺序；
- 每页核心问题；
- 每页核心证据；
- 每页结论。

## Step 3：确定页面比例

以用户本次要求为准。

不得套用固定比例。

## Step 4：确定版式

根据页面内容决定：

- 图文；
- 双栏；
- 三栏；
- 表格；
- 大图；
- 对比；
- 流程；
- 公式。

## Step 5：生成内容

先保证：

> 内容正确 > 逻辑清楚 > 版式合理

## Step 6：统一视觉

检查：

- 字体；
- 字号；
- 蓝色；
- 红色；
- 表格；
- 图片；
- 标题。

## Step 7：制作公式

有MathType：

> MathType优先。

没有：

> Office Math优先。

## Step 8：写Speaker Notes

每页必须完成。

## Step 9：程序化检查

检查：

- 页面比例；
- 字体；
- 字号；
- 备注；
- 表格；
- 公式；
- 图片。

## Step 10：渲染

将最终PPT渲染成：

- PDF；
- 或逐页图片。

## Step 11：视觉检查

逐页检查：

- 是否太空；
- 是否太挤；
- 是否溢出；
- 是否遮挡；
- 是否断行；
- 是否可读；
- 是否变形；
- 是否重点突出。

## Step 12：修改

发现问题后重新调整。

不能以：

> “PPT成功生成”

作为完成标准。

# 20. 自动检查与渲染验收

## 20.1 页面检查

必须检查：

- 实际页面宽度；
- 实际页面高度；
- 页面比例是否符合用户要求。

## 20.2 字体检查

检查所有可访问文本对象：

- 是否微软雅黑；
- 是否残留Arial；
- 是否残留Times New Roman；
- 是否残留Calibri；
- 是否残留其他普通字体。

## 20.3 字号检查

检查：

- 标题；
- 正文；
- 表格；
- 图题；
- 页脚；
- 图表文字。

重点发现：

> 非标准字号。

## 20.4 文本排版检查

检查：

- 溢出；
- 裁切；
- 重叠；
- 遮挡；
- 标题孤行；
- 数字单位断行；
- 页脚冲突。

## 20.5 页面密度检查

重点检查：

> **普通内容页是否明显过空。**

如果主要内容集中在页面中部且占比明显偏小，应重新布局。

优先：

- 放大图片；
- 放大图表；
- 扩大正文；
- 增加合理的结果解释；
- 调整双栏比例；
- 合并相关证据。

不要用装饰填空。

## 20.6 表格检查

检查：

- 表头颜色；
- 表体颜色；
- 字号；
- 对齐；
- 单位；
- 小数位；
- 表格是否过密；
- 是否可读。

## 20.7 公式检查

检查：

- 是否存在正式公式；
- MathType是否可用；
- 可用时是否优先MathType；
- 是否误用普通文本；
- 是否误用低清晰度截图。

## 20.8 Speaker Notes检查

检查：

> 每页是否100%存在Speaker Notes。

## 20.9 渲染检查

必须实际查看最终渲染结果。

至少检查：

- 页面是否太空；
- 页面是否太挤；
- 标题是否重叠；
- 正文是否被裁切；
- 表格是否可读；
- 图表是否可读；
- 图片是否变形；
- 红色是否过多；
- 页面视觉是否统一。

# 21. 最终交付标准

只有同时满足以下条件，才能判定 PPT 制作完成。

## 内容

- [ ] 内容来源明确；
- [ ] 数据没有擅自修改；
- [ ] 研究逻辑清楚；
- [ ] 每页有明确重点；
- [ ] 结论与证据匹配。

## 页面

- [ ] 页面比例符合用户本次要求；
- [ ] 页面没有明显无意义空白；
- [ ] 页面没有严重拥挤；
- [ ] 内容充分利用版心；
- [ ] 图片、表格和图表大小合理。

## 字体

- [ ] 普通文字全部微软雅黑；
- [ ] 英文和数字也是微软雅黑；
- [ ] 没有Times New Roman；
- [ ] 没有Arial；
- [ ] 没有Calibri；
- [ ] 没有其他非规定普通字体。

## 字号

- [ ] 常规正文优先24 pt；
- [ ] 信息密集页可使用16–18 pt；
- [ ] 表格正文12–14 pt；
- [ ] 标题层级统一；
- [ ] 没有大量自动缩放的小数字号。

## 颜色

- [ ] 蓝色建立结构；
- [ ] 黑色承载正文；
- [ ] 红色精准强调；
- [ ] 没有整段泛红；
- [ ] 没有无意义多色混搭。

## 表格

- [ ] 表格简洁；
- [ ] 表头统一；
- [ ] 字号可读；
- [ ] 单位规范；
- [ ] 小数位统一；
- [ ] 重点数据可局部红色；
- [ ] 没有为了塞内容而缩小到不可读。

## 图表

- [ ] 图片没有变形；
- [ ] 图表可读；
- [ ] 坐标轴和图例清楚；
- [ ] 图表真正服务于结论；
- [ ] 结果图没有缩得过小。

## 公式

- [ ] 有MathType且可调用时优先MathType；
- [ ] MathType公式保持可编辑；
- [ ] 无MathType时优先Office Math；
- [ ] 没有用普通文本模拟复杂公式。

## 演讲备注

- [ ] 每页100%有Speaker Notes；
- [ ] 备注不是简单复制正文；
- [ ] 备注能够用于实际汇报；
- [ ] 备注与当前页面内容一致；
- [ ] 没有编造数据和结论。

## 最终视觉

- [ ] 已实际渲染；
- [ ] 已逐页查看；
- [ ] 无溢出；
- [ ] 无遮挡；
- [ ] 无错误断行；
- [ ] 无明显空页；
- [ ] 无明显模板化；
- [ ] 无明显AI生成痕迹。

---

## 核心执行摘要

如果执行过程中只能记住最重要的规则，必须遵循以下原则：

> **1. 页面比例由用户每次指定，不得固定16:9。**

> **2. 页面要“铺满”，但不是贴满边缘；普通内容页应充分利用版心，避免大面积无意义空白。**

> **3. 所有普通中文、英文、西文、数字统一使用微软雅黑。**

> **4. 常规正文24 pt优先；20–22 pt用于较长正文；16–18 pt用于信息密集型页面；表格12–14 pt。**

> **5. 禁止用自动缩小字体解决内容过多。优先删减、重排、放大证据或拆页。**

> **6. 蓝色建立结构，黑色承载正文，红色只精准突出关键词、参数和结论。**

> **7. 允许“黑色完整句子 + 红色关键词”的局部强调，不允许整段泛红。**

> **8. 表格必须科研化、工程化、可读，不能缩成小字表格。**

> **9. 有MathType插件且可调用时，正式公式优先使用MathType；没有MathType时使用Office Math。**

> **10. 每张PPT必须有Speaker Notes，覆盖率100%。**

> **11. 生成PPT不是完成；必须实际读取、渲染、逐页检查并修改。**

> **12. 最终目标不是“做满一页”，而是“用足页面、讲清问题、突出证据、让专家一眼找到结论”。**
