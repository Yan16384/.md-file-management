## 一、共同翻译原则

- **准确 > 简单 > 清楚 > 易记 > 可复用 > 高级**。优先大学英语四级常见词汇和句式，能用 `use` 不用 `utilize`。
- 保留原文的主体、动作、时间、地点和因果、转折关系，不增添原文没有的意思。专业名称和固定术语优先准确，不为简单而误译。
- 语法正确前提下优先简单句、常见时态、主动语态。长句可拆成两个简单英文句，但不能改变意思。
- 不擅自扩写、机械润色或文学化。

## 二、英文长句切分与翻译规范

1. **基础切分**：按句号 `.`、问号 `?`、感叹号 `!` 切分长段落。
2. **超长句拦截（最高优先级）**：如果单句单词数超过 **20 个词**，必须在连词（如 `when`, `who`, `which`, `and`, `but`, `because`）或逗号处，强行打断为两个或多个短句。**绝对不允许出现长句堆砌！**
3. **引号处理**：遇到长段引语，引号内的完整句子必须单独切出。
4. **数据绑定**：切分出的每一个英文短句，必须独立翻译，采用 `{ en: "英文短句", cn: "精准中文翻译" }` 的格式，严禁跨句糅合翻译。

## 三、每篇文章独立生成词典与词组数据（防漏词）

> **通用规范不存词义**：本 Markdown 只定义 AI 生成规则和前端母版，不预置、积累或跨文章复用任何具体词汇、词组及其中文释义。每次用户提交新文章时，AI 必须根据当次文章独立识别单词和词组，并在本次输出的 HTML 中生成 `dict`、`phrasesDict` 和 `paragraphsData`。HTML 内嵌释义是离线查词所需的当次数据，不代表写回 Markdown 或建立长期词库。不得把上一篇文章的词典直接复制到下一篇。

> **词组识别原则**：AI 应结合当次文章上下文，识别真实的固定搭配、短语动词、习惯表达及有独立意义的常见词组；不要把任意相邻单词机械拼成词组。`phrasesDict` 每项包含 `meaning`（准确的语境中文释义），可选 `pos`，键为原文中实际出现的词组（小写）。词组词义也必须由 AI 每次重新生成。

> **【最高优先级指令】：词典必须进行“地毯式全量收录”**。
> 哪怕文章中出现了 200 个不同的单词，你也必须生成 200 个 key。**严禁以“该词太简单”为借口跳过 they, a, the, is, was, might 等任何基础词。如果你漏掉任何一个词，导致用户点击出现“未收录”，即视为任务失败！**

1. **多释义与词性拆解（核心强化）**：
   - **实词**：必须提供该词常见的 **前 3 到 5 个释义**（包含名词、动词、形容词等不同词性的衍生义）。
   - **虚词/功能词（如 than, it, that, a, the）**：绝不允许只给一个释义。必须将其在不同句型中的常见用法拆解开来（如 `than` 必须列出“比”、“与其说…不如”、“除了”、“刚…就”等至少 3-5 个释义），并提供多维度的中文翻译。
   - **排序原则**：所有释义必须严格按照**四六级考频和重要程度**从高到低排序，最常用的排在最前面。
2. **原形与变形词穷举兜底**：
   - 词条 key 必须使用词典原形（如 `making→make`）。
   - **例外情况**：文章中出现明显的不规则变形词（如 `women`, `has`, `was`, `been`, `better`）时，为了防止前端查词匹配失败，**必须在 `dict` 中将这些变形词作为独立的 key 录入**，并给出真实的音标和准确的释义。
   - 固定搭配和词组必须单独录入本次 HTML 的 `phrasesDict`；组成词组的每一个单词仍必须在本次 `dict` 中有独立释义。
3. **音标必填**：哪怕是数字（如 2000）或年份（如 1970s），也必须提供真实的音标（如 `/tuː ˈθaʊznd/`）。**严禁使用 `/-/` 敷衍了事！**
4. **语境高亮**：结合本文语境，判断该词对应哪一个释义，将其索引（从0开始）填入 `ctxIndex`。
5. **取消例句**：不需要生成 `ex` 字段，只保留音标、词性和释义。

## 四、前端 UI 与交互规范

1. **多主题适配**：网页自带白天、羊皮纸（护眼）、夜间三套主题，通过 CSS 变量控制。查词框和翻译框颜色随主题联动。
2. **左键查词**：悬浮窗显示音标、词性、按频次排序的全部释义（本文释义高亮加粗，其他释义以半透明或常规颜色展示）。若顶部空间不足自动向下弹。支持鼠标拖蓝选中文本（防误触查词），允许原生复制。
3. **词组预高亮与联合释义**：页面初次渲染时自动识别本次 `phrasesDict` 中出现在正文的词组，给词组内每个单词添加加深的主题色（不妨碍逐词点击、拖选复制和右键翻译）。点击词组内任意一个单词，查词框必须先完整展示该单词独立音标、词性及多义项，再在下方另起一行显示该词所在词组及其整体中文意思。若词组重叠，优先展示最长且符合语境的词组；同一单词可属于多个有意义的词组时可依次列出。词组匹配须遵守词边界，不跨句、不跨段，不把词组解释混入单词义项。
4. **右键看翻译**：鼠标右键点击某一句，该句下方出现绿色实线下划线并高亮，**在该段落正下方**（绝不悬浮遮挡）展开绿底边框的翻译框，显示当前句对应的中文。点击空白处自动收起。

## 五、严格输出与交付边界

1. **动态 DOM 渲染**：必须根据你切分的段落总数，动态增加或删除母版 HTML 中的 `<div class="paragraph" data-index="X"></div>`。确保 `data-index` 从 0 开始，与 `paragraphsData` 数组索引绝对一一对应。
2. **完整代码输出**：必须提供一个完整的、包含所有代码的 HTML 代码块（包含 `<!DOCTYPE html>` 到 `</html>`）。
3. **严禁省略**：严禁使用 `...` 或 `<!-- 省略部分 -->` 来省略代码。即使 CSS/JS 再长，也必须一字不漏地完整输出。
4. **文件命名**：在代码块上方用加粗字体标明建议保存的文件名，例如：`**请将以下代码保存为：YanReader-文章名.html**`。

function markPhrases() {
  const phrases = Object.keys(phrasesDict).sort((a, b) => b.split(/\s+/).length - a.split(/\s+/).length);
  document.querySelectorAll('.sentence').forEach(sentence => {
    const words = [...sentence.querySelectorAll('.word')];
    const normalize = x => x.toLowerCase().replace(/^[^a-z0-9]+|[^a-z0-9]+$/g, '').replace(/’/g, "'");
    const tokens = words.map(w => normalize(w.textContent));
    const assigned = new Set();
    for (const phrase of phrases) {
      const parts = phrase.toLowerCase().trim().split(/\s+/);
      for (let i = 0; i <= tokens.length - parts.length; i++) {
        if (parts.some((part, j) => tokens[i + j] !== part)) continue;
        // 最长优先，避免重叠词组覆盖。
        if (parts.some((_, j) => assigned.has(i + j))) continue;
        for (let j = 0; j < parts.length; j++) {
          words[i + j].classList.add('in-phrase');
          words[i + j].dataset.phrase = phrase;
          assigned.add(i + j);
        }
      }
    }
  });
}

  }
});
