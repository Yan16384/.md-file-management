# Yan 双模式翻译规范｜中译英 + 英文 HTML 阅读器（最新版）

> **用途**：本规范采用自动语言识别与双模式处理机制。用户发送中文段落时，执行中译英并直接输出简单、准确的英文文字；用户发送英文文章、英文段落或四六级阅读材料时，生成完整的 HTML 沉浸式阅读器。  
> **双模式原则**：中文 → 英文：优先使用大学英语四级常见词汇和简单语法，默认只输出英文译文。英文 → HTML：忠实保留英文原文，逐句翻译并生成完整阅读器。  
> **阅读器功能**：严格排除漏词、伪释义、无效音标、错误原形；保留词组预高亮、单词＋词组联合释义、右键翻译、题目独立排版及三主题。  
> **词库原则**：完整 HTML 母版不包含任何预存的单词词典、词组词典或中文词义；所有词义仅根据当次英文内容生成。  
> **优先级**：准确性与完整性高于词条数量；中译英时简单、准确优先于高级表达；阅读器检查不通过时必须修复后再交付，不能使用“未收录”作为正式成品的兜底。

## 一、使用范围与自动识别原则

### 1. 自动识别输入语言

根据用户实际提交的待处理内容判断模式，不根据用户输入指令的语言判断。

- 用户提交中文段落：默认进入 **中文 → 英文纯文本翻译模式**。
- 用户提交英文文章、英文段落、四六级阅读材料、英文题干及选项：默认进入 **英文 → HTML 阅读器模式**。
- 用户同时提交中文指令和英文文章：以英文文章为处理对象，默认生成 HTML。
- 用户明确指定其他任务、输出格式或处理方式时，优先遵循用户当次明确要求。
- 单个英文单词或短句，如果用户明确要求解释词义、语法或翻译，则按照具体要求处理，不自动生成整篇 HTML。

### 2. 中文 → 英文纯文本翻译模式

**触发条件**：用户直接发送中文段落、中文摘要、论文内容或其他中文文本，且没有指定其他任务。

这是独立的翻译模式，不生成 HTML，不启动阅读器词典。

#### （1）词汇难度

- **优先使用大学英语四级常见词汇和日常常用表达**。
- 能用简单词表达时，不使用不必要的高级词汇。
- 能用 `use` 不用 `utilize`，能用 `help` 不用 `facilitate`。
- 能用 `show`、`use`、`make`、`help` 等常见词表达时，不为追求词汇多样性而刻意替换成复杂同义词。
- 不刻意使用生僻词、GRE 词汇、文学化表达或过度正式的词汇。
- 不为了避免重复而强行更换词汇。重复使用准确、常见的词是允许的。
- 不机械限制每个单词必须出现在某一份固定的四级词表中。应优先选择四级常见词及其常用含义，必要的专业术语、固定名称和准确表达除外。
- 不得为了降低难度而使用不符合语境的简单词，也不得把专业术语替换成含义不准确的普通词。

示例：

| 优先使用 | 不必要时避免 |
|---|---|
| use | utilize |
| help | facilitate |
| show | demonstrate |
| important | significant |
| many | numerous |
| need | necessitate |
| make | formulate |

以上仅用于说明难度取舍，不代表右侧词汇在所有语境中都不能使用。

#### （2）语法难度

- 优先使用简单句、常见时态和主动语态。
- 优先使用主谓宾等清楚、容易理解的句子结构。
- 尽量减少多层从句、复杂非谓语结构、倒装、虚拟语气和不必要的完成进行时。
- 避免一个英文句子包含过多层次的逻辑关系。
- 中文长句可以根据语义拆分为两个或多个简单英文句，但必须保持原文逻辑和含义。
- 不为了体现英语水平而使用复杂句型。
- 语法必须正确，不能为了简单而省略必要的主语、谓语、连接词或其他语法成分。
- 简化句式不能改变原文的因果、条件、转折、递进、比较和时间关系。

#### （3）忠实翻译

- 保留原文的主体、动作、对象、时间、地点和逻辑关系。
- 准确保留否定、程度、因果、条件、转折、递进和比较关系。
- 不擅自增加原文没有的信息，不随意删除重要信息。
- 不擅自扩写、文学化、机械润色或改变原文的表达重点。
- 专业术语、专有名称和固定搭配必须准确。不能为了使用四级词汇而误译专业内容。
- 遇到专业性较强的中文论文内容，应优先保证专业准确性，同时尽量将其他部分写得简单清楚。
- 如果某个概念没有准确、自然的四级常见词对应，可以使用必要的专业词或更准确的常见表达，不得强行替换。

#### （4）固定输出格式

**默认只输出英文译文，不输出中文原文。**

具体要求：

- 不添加中文原文。
- 不添加“原文”“译文”“Translation”等标签。
- 不添加逐句解释、词汇分析、语法讲解或翻译思路。
- 不添加无关的开头、结尾和总结。
- 不使用表格。
- 不生成 HTML、代码块或词典。
- 保留原文合理的段落划分，直接输出英文段落。
- 用户要求其他排版时，以当次要求为准。

**最终效果：用户发送中文，直接收到可以复制使用的英文译文。**

### 3. 英文 → HTML 阅读器模式

**触发条件**：用户发送英文文章、英文阅读段落、四六级阅读理解材料、题干及选项，默认生成完整的离线 HTML 文件。

本模式沿用本规范原有的阅读器、词典、词组、界面、数据校验及 HTML 母版要求。

特别注意：

- 英文原文必须忠实保留，不擅自改写、简化或替换原文词汇。
- 对英文原文进行逐句中文翻译，保持原文和译文对应。
- 对原文实际出现的单词进行完整词典提取。
- 词典中的单词释义以准确、常用、符合四六级学习需求为主。
- 专业词汇和必要的高级词汇仍需准确解释。
- 不得把中文 → 英文模式中的四级简单词汇限制错误地应用到英文原文或英文词典。
- 保留词典完整性、词组预高亮、联合释义、音标、词性、原形提示及全部现有交互功能。
- 用户只要求翻译时，不擅自增加答案、判题、评分或答案解析。

### 4. 用户明确要求优先

自动识别是默认行为，不是对用户当次要求的限制。

例如：

- 发送中文段落：默认直接翻译成英文。
- 发送英文文章：默认生成 HTML。
- 发送中文段落并明确要求逐句解释：按照明确要求处理。
- 发送英文文章并明确要求只翻译全文：按照当次要求处理。
- 明确要求完整 HTML 源码：输出完整源码，不用下载文件代替。
- 明确要求解题、答案或解析：仅在用户明确要求时提供，不因阅读器模式自动添加。

## 二、双模式通用翻译原则与英文内容排版

### 1. 两种模式的边界

- 中文 → 英文模式的目标是帮助用户获得**简单、准确、容易掌握、符合四级常见词汇水平**的英文表达。
- 英文 → HTML 模式的目标是帮助用户阅读和理解**用户实际提供的英文原文**，不得把原文改写成简单英语。
- 四级词汇偏好只约束中译英的英文译文，不约束英文原文、专业术语、词典音标或词典释义。
- 两种模式都必须保证含义准确，不得为了追求简单而牺牲语义。

### 2. 文章模式

- 按原段落顺序显示，段落内部支持逐短句右键查看翻译。
- 保留英文原文的段落、引语和合理标点。
- 每个英文短句对应准确的中文翻译。

### 3. 试题模式

- 每道题独立区块，题号和题干清晰分开。
- A、B、C、D **各自独占一行**、左对齐、统一缩进。
- 每个选项单独对应一份中文翻译，不能拼在同一行或合并翻译。
- 不擅自添加正确答案、答题按钮、评分或答案解析。
- 只有用户明确要求答案或解析时，才额外提供相应内容；若用户要求的是 HTML 翻译阅读器，仍须保持题目与选项的独立排版。

### 4. 混合模式

- 先文章、后题目，也可保留用户指定的原始顺序。
- 共享当次词典，但译文逐项独立。
- 文章、题干和选项不得相互拼接或混淆。

### 5. 移动端与电脑端

- 移动端选项在自己的一行内部自然换行，不挤到下一选项。
- 手机提供“译”按钮，电脑仍支持鼠标右键。
- 所有主题下均应保持选项分行、翻译框和词典弹窗清晰可读。

## 三、英文短句切分与对应翻译

1. 文章先按句末标点划分；**超过 20 个英文词的句子**应优先在逗号、连词、从句边界进一步拆成便于学习的短句。不可把词语任意截断或改变原文含义。
2. 引语中的完整句子分别处理。拆分时保留原顺序和标点；连续短句在页面上仍应自然阅读。
3. 每一段文章保存为一个 `type: "paragraph"` 内容块，其 `segments` 为 `{ en, cn }` 的数组；每个英文短句对应一个准确的中文翻译。
4. 试题的**题干及每个选项**优先保持各自为一个可独立翻译的单位；即使单项超过 20 词，也不能破坏 A/B/C/D 选项结构。
5. 不提供任何额外答案标记。题干与选项的英文展示内容**不需要再把题号和 A/B/C/D 字母写入 `en` 字段**：由试题数据的 `number` 与 `label` 单独渲染，以防重复显示。

## 四、每次独立生成词典：零漏词、零占位

**这是最高优先级规则。**

1. **先提取词面，再生成释义**：必须对本次 `paragraphsData` 中每个 `en` 做完整分词，取出所有实际上会被网页渲染为可点击 `.word` 的 token，统一大小写及撇号形式后去重。按这些词面逐一创建 `dict` 键，不得只为词典原形建键。
2. **表面词形必须直接命中**：过去式、过去分词、复数、比较级、最高级、缩写、撇号缩约词、连字符复合词、年份及百分数——只要在网页中可点击，就必须有**与该显示词面一一对应的独立条目**。前端禁止以截去 `-s/-ed/-ing` 等方式猜词；不得依赖“查不到就试试其他词条”。
3. **每项必须有真实信息**：至少包括 `ph`（该词形的准确 IPA）、`pos`（准确词性，例如 `v.`、`n.`、`adj.` 等）、`means`（具体中文义项数组）、`ctxIndex`（当前上下文含义在 `means` 中从 0 开始的索引）。变形词还必须在适用时带 `lemma`（真实词典原形）。
4. **不准使用假内容**：严格禁止 `/-/`、`（词典未收录该词）`、`基本含义`、`相关用法`、`引申含义`、`常见搭配`、`文章中的词语`、`词性/用法`、`具体含义依语境而定`、`TODO` 等占位字样；不能假装完成释义。
5. **释义重质量，不凑数量**：优先给 3—5 个高频、确有区别的义项（有需要时区分词性），但若某个词只有 1—2 个真实常用用法，就只写 1—2 项；绝不为满足数量编造同义重复、冷僻错义或不自然解释。功能词需要明确说明不同常见语法用法，而不是重复“相关表达”。
6. **语境必须对应**：`ctxIndex` 指向文中**真正适用**的义项。若同一词形在不同句子中的义项不同，可在对应句子数据加入 `ctxOverrides`（映射 `词面: 义项索引`）；页面据此逐次高亮，不能对所有出现位置一概高亮第一个含义。
7. **原形只做提示**：只有确属变形形式才填 `lemma`，例如过去分词、复数或比较级；原形词、独立派生词、已词汇化用法等不得机械标记原形。弹窗大词右侧以浅灰小字显示 `原形：…`；原形不替代当前词形自身的音标或释义。
8. **音标核验**：使用适当的英语音标书写，且应匹配**当前词形的实际读音**。年份、数字与百分比也需提供真实可读形式，不能根据字母随意拼凑发音。
9. **不添加例句字段**：词典数据不需要 `ex`。若本次文章不含某单词，也不需要为其额外生成词条。

<a id="section-5"></a>
## 五、词组识别、预高亮及联合释义

1. 本次 `phrasesDict` 由 AI 阅读**本次**内容后生成，只收录真实固定搭配、短语动词、惯用表达和意义明确的词组；不机械拼接任意相邻两词。
2. key 为对应正文里实际连续出现的词组（建议统一小写），value 是 `{ meaning: "本次准确中文释义" }`。**这里的提示只是数据字段形式，不是预存的词组释义。**
3. 页面初次渲染时，词组所有成员单词自动加深主题色并加轻下划线，**无需点击才高亮**。
4. 点击词组中任意一个单词时，弹窗先显示这个**单词本身**的音标、词性、多义项和可选原形提示，然后再显示其所在的词组与整体中文含义。
5. 词组匹配只在同一个句子单位内进行，不跨句、不跨选项、不跨段；出现多个重叠词组时先显示较长的表达，也可按序显示其他有意义的匹配。
6. 词组内部每个独立可点击单词仍必须在 `dict` 中有自己的真实释义。

## 六、界面规范

1. 白天、羊皮纸、夜间三种主题，CSS 变量驱动。词组高亮、查词弹窗、中文翻译框均适配主题。
2. 单词左键或手机点击：打开悬浮弹窗，标题为大号粗体单词，右侧小字可显示 `原形：…`；第二行音标，第三部分真实词性和各个释义。**当前语境义项加粗高亮**，其他义项保持可读。
3. 词组额外解释位于独立释义后面的分隔区域，不挤进单词义项序号中。
4. 电脑右键点句显示当前中文翻译；文章译文在对应**段落下方**展开，试题每项译文在对应**题干或选项下方**展开，不使用遮住正文的悬浮翻译框。点击空白可收起。
5. 允许鼠标原生拖蓝选中并复制，不能把拖选误判成查词；悬浮查词框应限制在可视区域内。
6. 不附加答题按钮、评分功能、答案颜色提示或后台服务。

<a id="section-7"></a>
## 七、数据结构与生成约束

以下是**字段格式说明，不是词典内容**，不得直接把尖括号中的文字作为实际释义生成进 HTML。

```text
const dict = {
  "<当次出现的词面，转小写>": {
    ph: "<当前词形的真实音标>",
    pos: "<真实词性>",
    means: ["<真实中文含义1>", "<真实中文含义2>"],
    ctxIndex: 0,
    lemma: "<仅变形词才填的准确原形，可省略>"
  }
};
const phrasesDict = {
  "<本次真实出现的多词表达>": { meaning: "<准确整体中文含义>" }
};
const paragraphsData = [
  { type: "paragraph", segments: [
    { en: "<英文短句>", cn: "<逐句中文>", ctxOverrides: {} }
  ] },
  { type: "question", number: "<题号>",
    stem: { en: "<英文题干，不含题号>", cn: "<中文题干>" },
    options: [
      { label: "A", en: "<A的英文内容，不含字母>", cn: "<A的中文翻译>" },
      { label: "B", en: "<B的英文内容，不含字母>", cn: "<B的中文翻译>" },
      { label: "C", en: "<C的英文内容，不含字母>", cn: "<C的中文翻译>" },
      { label: "D", en: "<D的英文内容，不含字母>", cn: "<D的中文翻译>" }
    ]
  }
];
```

- 具体生成时必须**删除不适用的示意内容、填入用户当次实际数据**。文章模式不生成空题目；试题模式不生成空文章。
- 页面所有 `.paragraph` 按 `paragraphsData` 顺序动态创建，`data-index` 从 0 开始一一对应。试题区块也有自己的顺序索引和独立结构。
- 分词规则和词典建键规则必须与母版 JavaScript 的 `tokenPattern`、`normalize()` 保持**完全一致**；先按该规则提取词面，再生成 `dict`。
- 此 Markdown 的母版中，`dict = {}`、`phrasesDict = {}`、`paragraphsData = []` 均为空，绝不预置实际词义；每次只把本次词典写进**当次输出的 HTML**，不反向写回规范。

## 八、生成前强制质量检查与禁止交付条件

**AI 应完成两层检查：**

### A. 生成期内容审查

- [ ] 完整保留每个原文段落或题干、原始题号、四个选项；选项 A/B/C/D 各占一行。
- [ ] 逐句对应翻译，否定、程度、时态、专有术语没有翻错；用户只要翻译时不出现答案或解析。
- [ ] 使用同一分词器从所有 `en` 提取出现词面，检查 `dict` 中每个词面**精确存在**，而不仅是其原形存在。
- [ ] 无空词典项、无占位词义、无 `/-/` 音标、无“词性/用法”等含糊字段。
- [ ] 对所有出现的缩约词、连字符词、数字、年份及变形词单独检查；原形与实际语法身份一致。
- [ ] `ctxIndex` 和可选的 `ctxOverrides` 指向真实现存的义项，音标、词性及中文含义经过语义审查。
- [ ] 词组本次独立生成，显示前自动高亮；任意成员词点击时先单词后词组。
- [ ] 本 Markdown 未保存任何当次词义；不得把上次生成的 `dict` 或 `phrasesDict` 作为长期词库。

### B. HTML 自动校验

- 模板中 `audit()` 在渲染后逐一检查**所有可点击单词**是否有词面精确对应的词条，并检测缺词、无效 IPA 字段、空词性、占位释义、错误索引、缺失翻译及不完整 A/B/C/D。
- 如果 `audit()` 报告问题，AI 必须修复生成数据、重新运行检查，直到结果为零；**不允许把报错页面当成完成品交付**。
- 自动校验只能检查数据结构与明显占位问题，**不能保证音标、中文义项语义一定正确**；AI 仍须人工式逐项语义核对，不得把“校验通过”等同于“释义准确”。
- 推荐生成后在浏览器中实际点测长词、变形词、缩写及四个选项，检查主题、鼠标右键和手机“译”。

function appendTokenizedText(parent, en, overrides = {}) {
  const regex = new RegExp(tokenPattern.source, "g");
  let cursor = 0, match;
  while ((match = regex.exec(en)) !== null) {
    if (match.index > cursor) parent.append(document.createTextNode(en.slice(cursor,match.index)));
    const w = document.createElement("span");
    w.className = "word";
    w.textContent = match[0];
    w.dataset.key = normalize(match[0]);
    w.dataset.start = String(match.index);
    w.dataset.end = String(regex.lastIndex);
    const index = overrides[w.dataset.key];
    if (Number.isInteger(index)) w.dataset.ctxIndex = String(index);
    parent.append(w);
    cursor = regex.lastIndex;
  }
  if (cursor < en.length) parent.append(document.createTextNode(en.slice(cursor)));
}

function markPhrases() {
  const phrases = Object.keys(phrasesDict).sort((a,b) => b.length - a.length);
  document.querySelectorAll(".sentence").forEach(sentence => {
    const words = [...sentence.querySelectorAll(".word")];
    const keys = words.map(w => w.dataset.key);
    const raw = sentence.textContent;
    for (const phrase of phrases) {
      const parts = phrase.trim().split(/\s+/).map(normalize);
      if (!parts.length) continue;
      for (let i = 0; i <= words.length-parts.length; i++) {
        if (!parts.every((x,j) => keys[i+j] === x)) continue;
        let continuous = true;
        for (let j=0; j<parts.length-1; j++) {
          const gap = raw.slice(Number(words[i+j].dataset.end),Number(words[i+j+1].dataset.start));
          if (!/^\s+$/.test(gap)) { continuous=false; break; }
        }
        if (!continuous) continue;
        for (let j=0; j<parts.length; j++) {
          const w = words[i+j];
          const hits = phraseHits.get(w) || [];
          if (!hits.includes(phrase)) hits.push(phrase);
          phraseHits.set(w,hits);
          w.classList.add("in-phrase");
        }
      }
    }
  });
}
function audit() {
  const errors = [];
  const prohibited = /未收录|文章中的词语|相关表达|具体含义依语境|基本含义|相关用法|引申含义|常见搭配|待补充|暂无释义|词性\/用法|TODO|占位/i;
  if (!Array.isArray(paragraphsData) || !paragraphsData.length) errors.push("未填入本次文章或试题数据");
  paragraphsData.forEach((b,i) => {
    if (!b || !["paragraph","question"].includes(b.type)) {
      errors.push("内容块 #"+i+" 类型错误"); return;
    }
    const items = b.type === "paragraph" ? b.segments : [b.stem,...(Array.isArray(b.options) ? b.options : [])];
    if (!Array.isArray(items) || !items.length) errors.push("内容块 #"+i+" 缺少句子");
    else items.forEach((x,j) => {
      if (!x || typeof x.en !== "string" || !x.en.trim() ||
          typeof x.cn !== "string" || !x.cn.trim()) errors.push("内容块 #"+i+" 第"+(j+1)+"项缺失原文或翻译");
    });
    if (b.type === "question") {
      if (!b.stem || !Array.isArray(b.options) || b.options.length !== 4 ||
          b.options.map(o=>o.label).join("") !== "ABCD")
        errors.push("第"+String(b.number)+"题缺少完整的 A/B/C/D 选项");
    }
  });
  const keys = [...new Set([...document.querySelectorAll(".word")].map(w=>w.dataset.key))];
  for (const key of keys) {
    if (!Object.prototype.hasOwnProperty.call(dict,key)) {
      errors.push("缺少词条："+key); continue;
    }
    const entry = dict[key];
    if (!entry || typeof entry !== "object") { errors.push("词条结构错误："+key); continue; }
    if (typeof entry.ph !== "string" || !/^\/[^/]{2,}\/$/.test(entry.ph) || entry.ph === "/-/")
      errors.push("音标无效："+key);
    if (typeof entry.pos !== "string" || !entry.pos.trim() || prohibited.test(entry.pos) || !/[a-z]/i.test(entry.pos))
      errors.push("词性无效："+key);
    if (!Array.isArray(entry.means) || !entry.means.length || entry.means.length>6 ||
        entry.means.some(m=>typeof m!=="string" || !m.trim() || prohibited.test(m)))
      errors.push("释义缺失、占位或数量异常："+key);
    else if (new Set(entry.means.map(m=>m.trim())).size !== entry.means.length)
      errors.push("释义重复："+key);
    if (!Number.isInteger(entry.ctxIndex) || !entry.means || entry.ctxIndex<0 || entry.ctxIndex>=entry.means.length)
      errors.push("语境索引错误："+key);
    if (entry.lemma!==undefined && (typeof entry.lemma!=="string" || !entry.lemma.trim() || normalize(entry.lemma)===key))
      errors.push("原形提示错误："+key);
  }
  document.querySelectorAll(".word[data-ctx-index]").forEach(w => {
    const value = Number(w.dataset.ctxIndex), entry = dict[w.dataset.key];
    if (!entry || !Number.isInteger(value) || value<0 || value>=entry.means.length)
      errors.push("句内语境索引错误："+w.dataset.key);
  });
  Object.entries(phrasesDict).forEach(([key,v]) => {
    const meaning = typeof v === "string" ? v : v && v.meaning;
    if (!key.trim() || typeof meaning !== "string" || !meaning.trim() || prohibited.test(meaning))
      errors.push("词组释义无效："+key);
  });
  return [...new Set(errors)];
}

function showWord(word) {
  if (!validationOk || String(window.getSelection()).trim()) return;
  hideTip();
  word.classList.add("active");
  const key=word.dataset.key;
  const item=dict[key]; // 只做词面精确查找；不使用词尾裁剪猜测词义。
  wordTip.replaceChildren();
  const heading=addText(wordTip,"div","word-heading","");
  addText(heading,"span","head-word",word.textContent);
  if (item.lemma && normalize(item.lemma)!==key)
    addText(heading,"span","lemma","原形："+item.lemma);
  addText(wordTip,"div","phonetic",item.ph);
  const meaning=addText(wordTip,"div","meaning","");
  addText(meaning,"span","pos",item.pos);
  const selected=word.dataset.ctxIndex!==undefined?Number(word.dataset.ctxIndex):item.ctxIndex;
  item.means.forEach((x,i) => addText(meaning,"span","mean "+(i===selected?"contextual":"other"),String(i+1)+". "+x));
  (phraseHits.get(word) || []).forEach(phrase => {
    const phraseData=phrasesDict[phrase];
    const block=addText(wordTip,"div","phrase-part","");
    addText(block,"div","phrase-name","词组："+phrase);
    addText(block,"div","phrase-cn",typeof phraseData==="string"?phraseData:phraseData.meaning);
  });
  wordTip.classList.add("show");
  const r=word.getBoundingClientRect();
  const width=wordTip.offsetWidth, height=wordTip.offsetHeight;
  const left=Math.max(10,Math.min(innerWidth-width-10,r.left+r.width/2-width/2));
  const above=r.top-height-9;
  const top=above>=8?above:Math.min(innerHeight-height-8,r.bottom+9);
  wordTip.style.left=left+"px";
  wordTip.style.top=Math.max(8,top)+"px";
}
function showTranslation(sentence) {
  if (!validationOk) return;
  const host=sentence.closest(".question-line") || sentence.closest(".paragraph");
  if (!host) return;
  const box=host.querySelector(":scope > .trans-box");
  const wasOpen=box && box.classList.contains("show") && sentence.classList.contains("active-sent");
  document.querySelectorAll(".sentence.active-sent").forEach(el=>el.classList.remove("active-sent"));
  document.querySelectorAll(".trans-box.show").forEach(el=>el.classList.remove("show"));

  if (box && !wasOpen) {
    box.textContent=sentenceCN.get(sentence) || "";
    box.classList.add("show");
    sentence.classList.add("active-sent");
  }
}
